  • + 복제에 쿼리 슬롯 0 소모 (Colossus 백그라운드 전담)
  • + Managed DR(Enterprise+) 구성 시 RTO 5분 내 슬롯·스토리지 승격 · 멀티리전 10 PB / 단일 리전 500 TB+ 확장
  • + dataset_staleness 지표로 복제 지연 실시간 관측
단점
  • − Secondary는 승격 전까지 엄격한 Read-Only (Standard CRR은 Primary 생존 시에만 승격 가능, Primary 장애 시 Hard Failover는 Managed DR 전용)
  • − Policy Tag 및 연결된 Data Policy는 복제 제외
  • − 스트리밍(Write API/insertAll) · CDC 적재는 복제가 Best-Effort
  • − 대상 리전 KMS(CMEK) 듀얼 프로비저닝(replica_kms_key) 필수 및 BigLake/Fine-grained DML 미지원

  • − 변경된 테이블은 전체 재전송(Truncate & Replace) — 행 단위 증분 아님 (※복제본 직접 수정 시 다음 배치에 데이터·스키마 덮어써짐)

  • − 크로스 리전 CDC 테이블 및 Policy Tag 테이블 복사 불가

  • + 타겟은 완전 독립 테이블 — 복제 직후 즉시 쓰기(DML/DDL)·스키마 변경·가공 가능
  • + 필요한 테이블만 골라 일회성 Egress 발생 (기본 일 2,000회 / 테이블당 일 100회 쿼터)

Q1. Global Queries
(Cross-Region SQL)		 • 복제 없이 즉시 조인
• SET @@location 지정만 언급 		• 실행 시 원격 서브쿼리 결과를 Primary 리전 임시 테이블로 전송·24시간 보관하며 Data Replication 전송비 + 24h 스토리지 과금 발생
• ALTER PROJECT SET OPTIONS로 실행/데이터 접근 옵션 사전 활성화 필수 (단일 Copy Job 100 GB 상한) 		🔗 Global queries 공식 문서 🔗 Query jobs Quotas (100 GB)
Q2 & Q3. CRR vs
Managed DR (Turbo)		 • Q2 배지 [CRR] 표기
• Dataset Replication — Turbo Mode
• Standard Mode = 비용 최적화 DR 		• Q2 배지를 출시 단계인 [GA]로 통일
• 15분 RPO·5분 RTO 및 Primary 장애 시 Hard Failover는 Managed DR (Enterprise Plus 예약 필수, 대륙 내 페어 한정) 전용
• Standard CRR은 Primary 생존 시에만 승격(Soft Promotion) 가능하며 Primary 전면 장애 시 승격 불가 		🔗 Managed Disaster Recovery 🔗 CRR vs DR 기능 차이 비교표 🔗 Cross-region dataset replication

Q5 & Card 3.
Native Table Copy
(bq cp, CRTC)		 • 일회성 Egress만 발생, bq cancel로 중단 용이
• 물리 1 TiB 초과 시 ~10% 실패율 — GA 보류 		• 작업 완료 전 bq cancel로 취소하더라도 기전송된 데이터에 대한 크로스 리전 복제 요금이 부과됨
• 퍼블릭 문서는 물리 20 TiB 상한(1 TiB 초과 시 다중 재시도 필요)로 명시
• 내부적으로는 구형 Effingo를 대체한 신형 CRR 기반 CRTC 엔진(최대 30 TB, 1 Gbps 보장)이 26년 7월 Wave 5 롤아웃 완료 		🔗 Copy tables across regions (과금 경고) 🔗 Table copy Limitations (20 TiB) 사내: launch/4364631, b/214591611
